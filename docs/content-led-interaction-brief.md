# Content-Led Interaction Brief

Owner feedback on 2026-10-15 supersedes the abstract spatial-introduction direction. This is the implementation brief applied in this revision, not a request for the owner to write another prompt.

## Applied Prompt

Build a personal research notebook that visitors can explore through its actual projects, research questions, diagrams, and approved application screens. Introduce Gnaroshi before the tools. Preserve the existing identity, restrained orange/teal palette, English navigation, Korean content, public-feed contract, and truthful project status.

Every substantial interaction must name its content object, visitor action, changed information, and useful next destination. Reject unrelated geometry, simulated research results, repeated decoration, hidden-only effects, and adding a renderer merely to check a technology box. Do not ask the owner for another reference when the accumulated brief is sufficient.

- Home: make real project evidence discoverable in the first reading path. Selecting or dragging the work changes its approved screenshot, actual story, limitations, workflow, and detail link. Preserve depth with browser CSS composition, not an engine or ambient render loop.
- Research: connect the selected question to its motivation, hypothesis, uncertainty, and approved figure. Visitors can drag between questions, compare positions, and zoom/pan the actual technical figure. Do not turn an unrelated surface into a pretend research landscape.
- Projects: let visitors browse by purpose and inspect named captured scenario steps. Keep the previous image until the requested image has decoded, prevent stale responses from replacing newer selections, and fetch inactive captures on demand. Actual product status, limitations and disclosure remain visible.
- About: retain the specifically requested three-click identity relief and six-click foil. Import Three.js only after that explicit action; do not run a second background renderer.
- Articles, profile/status/contact pages and evidence-gated tool routes: retain reading, navigation and existing contextual controls. Do not advertise absent capabilities or add empty interactive toys to claim every route has an animation.

Measure the experience the owner sees: development and production separately, startup and real input separately, ordinary and throttled CPU, desktop and touch. FPS caps and successful builds are not evidence of responsiveness. Record actual script requests, main-thread input work, long tasks, idle activity, overlap, and decoded media. Keep static/no-JavaScript, reduced-motion and keyboard paths complete.
