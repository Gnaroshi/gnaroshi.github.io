# English And Korean Localization

## URL Policy

- English is the default locale and keeps the existing unprefixed URLs, such as `/blog/` and `/papers/`.
- Korean uses the `ko` locale and the `/ko/` prefix, such as `/ko/blog/` and `/ko/papers/`.
- Do not add `/en/` or `/kr/` routes.
- Never redirect solely from `navigator.language`. The language switch records an explicit choice but navigation remains user initiated.

Astro's i18n configuration is in `astro.config.mjs`. Locale types, dictionaries, routing helpers, date formatting, and tag labels live under `src/i18n/`.

## Page Architecture

Root and `/ko/` route files are thin wrappers. Shared page implementations live in `src/views/` and receive a typed `locale` prop. Business logic, collection queries, and dashboard calculations must remain shared.

`BaseLayout.astro` owns the document language, localized shell, canonical URL, `hreflang` links, Open Graph locale, header, and footer. React islands receive both `locale` and a typed subset of `IslandMessages`; do not import an English-only label table into an island.

## Static Data

Locale-aware profile, research, project, skill, and current-focus data live in `src/data/locales/`. English may reference the canonical source data. Korean copy must preserve the same facts and omit unknown fields rather than inventing values.

## Localized Feed Content

The public feed provides locale, translation key, and source metadata. The website adapts those fields for rendering but does not author or translate content records.

Feed blog paths use locale folders:

```text
.content-feed/blog/en/<slug>.mdx
.content-feed/blog/ko/<slug>.mdx
```

Paper paths follow the same structure:

```text
.content-feed/papers/en/<slug>.mdx
.content-feed/papers/ko/<slug>.mdx
```

The locale directory is removed from the public slug. The publisher pairs translations with `translationKey`; the website never guesses from filenames. Article content, dates, and task copy follow the locale. Owner-selected global navigation stays English in both locales: Home, Research, Projects, Blog, Papers, About, Activity, Now, and Links. This includes mobile, footer, and site-owned breadcrumb labels; actual document titles retain their language.

Paired content switches directly to its counterpart. When no counterpart exists, the alternate language opens a compact disclosure with the missing-translation state and an explicitly named link to that language's collection. Do not show permanent translation warnings, duplicate language badges above the title, or promise that a translation is in preparation. Current locale stays inert. Test keyboard, Escape, outside click, mobile focus, and both paired/unpaired states.

Blog discovery is independent of the interface language. The index, archive, tags,
Home's recent writing, related writing and RSS include every public post family,
grouped only by its declared `translationKey`. Prefer the requested locale when a
real public version exists; otherwise link to the available version's actual
locale route. Never render another language's article under a fabricated detail
URL. A later public translation appears automatically in that family without
duplicating its list entry. Paired entries offer compact links to their real EN/KO
versions; single-language entries need no warning or promised translation. Search
results use the record's locale, not the interface locale, for their destination.
RSS channels retain the requested preference and identify each item's actual
language with `dc:language`. Production discovery excludes hidden, unlisted and
draft records; detail-route and translation privacy rules are unchanged.

Papers follows the same collection preference: show each public paper-note family
once and retain the selected record's actual language URL. A Korean-only note is
discoverable from both collection interfaces without creating an English detail
page. Public paper notes enable Papers navigation in both locales; a truly empty
collection retains its existing compatibility redirect. Reading methods, numbered
passes and practice controls are retired, not translated into a new set of labels.

## Writing Korean Copy

- Write Korean independently from the shared facts and intended meaning; do not translate English sentence structure line by line.
- Prefer ordinary verbs such as `공부합니다`, `만들고 있습니다`, `살펴보고 있습니다`, and `기록합니다` over stacked technical nouns.
- Keep public introductions personal and concrete. Internal publishing and metric vocabulary belongs in technical detail or developer documentation.
- Keep paper titles, model names, dataset names, code, formulas, GitHub, Astro, React, and MDX unchanged unless an official Korean name exists.
- Keep canonical tag IDs language-neutral and localize display labels in `src/i18n/tags.ts`.
- Use `formatLocalizedDate` and `formatLocalizedNumber`; do not hand-format dates or counts.
- Follow `docs/i18n-terminology.md` for recurring product language.
- Follow `docs/public-voice.md` for tone, privacy, title, and page-ownership rules.

## Verification

Run the build before generated-output checks:

```bash
npm run check
npm run check:i18n
npm run build
npm run check:public-tone
npm run test:e2e
```

`check:i18n` enforces exact key parity, non-empty values, placeholder rejection, and accidental English-copy detection. Route and alternate-link behavior remains covered by Playwright.
