공개 흐름

공개 웹사이트가 미완성 기록과 초안의 저장소가 되어서는 안 됩니다.

비공개 논문·글 저장소, 로컬 발행 도구, 정제된 공개 피드, 표시 계층을 역할별로 나눈 구조입니다.

  • 비공개 원본 저장소를 따로 체크포인트합니다.
  • 발행 도구가 같은 입력에서 같은 공개 피드를 만듭니다.
  • 웹사이트가 피드를 검증하고 빌드한 뒤 배포 결과를 확인합니다.

저장소 경계

  • Paper Lab과 Writing이 비공개 원본을 소유합니다.
  • Studio가 작성과 발행을 맡습니다.
  • Content Feed가 생성된 공개 기록을 소유합니다.
  • gnaroshi.dev는 표시만 맡습니다.

사용 흐름

공개까지의 흐름

검토한 기록 하나가 비공개 작성에서 배포 확인까지 가는 과정을 봅니다.

  1. 1

    비공개로 작성

    원본 기록을 역할에 맞는 비공개 저장소에서 편집합니다.

  2. 2

    공개 항목 확인

    공개 피드에 넣을 항목만 골라 다시 확인합니다.

  3. 3

    피드 발행

    정제한 공개 자료를 만들고 검증한 뒤 차이를 확인해 푸시합니다.

  4. 4

    사이트 확인

    build-info.json의 웹사이트와 피드 커밋이 예상값과 같은지 확인합니다.

설명용 저장소 상태를 사용하며 비공개 내용은 노출하지 않습니다.

이 사이트의 구조

발행 작업 흐름: 기록이 공개되기까지

논문과 글은 비공개로 작성합니다. Studio에서 공개할 내용을 확인한 뒤, 공개용 데이터로 정리해 이 사이트에 반영합니다.

Studio 앱

Studio가 연결하는 독립 실행 앱

이 앱들은 웹사이트 발행 흐름의 저장소가 아닙니다. Studio가 상태를 확인하고 열거나 전달 내용을 미리 볼 수 있지만, 각 앱은 독립적으로 실행되며 자체 데이터를 유지합니다.

배포 확인

  • GitHub Actions가 정적 결과물을 만듭니다.
  • 배포된 build-info와 예상 커밋을 비교합니다.

주요 기능

  • 영문·국문 경로
  • 공개 피드 검증
  • 근거가 있을 때만 보이는 탐색과 지표
  • GitHub Pages 배포 출처 기록

데이터와 개인정보

웹사이트 빌드는 비공개 논문·글 저장소를 체크아웃하지 않으며 저장소 간 비밀 정보도 받지 않습니다.

기술 구성

프레임워크

  • Astro
  • Playwright

언어

  • TypeScript

배포

  • GitHub Actions

기술 아이콘은 저장소에 포함된 범주 심볼이며, 실제 기술 이름을 함께 표시합니다.

Studio와의 관계

Studio가 공개 피드를 준비하고 발행하지만 웹사이트 저장소를 직접 쓰지는 않습니다.

현재 상태

공개 콘텐츠 피드로 빌드하고 GitHub Actions로 배포하며 실제 웹사이트와 피드 커밋을 확인합니다.

현재 한계

  • 검토한 기록이 공개되기 전까지 글과 논문 읽기 영역은 의도적으로 작게 유지됩니다.

기술 메모

  • Astro가 클라이언트 자바스크립트를 최소화한 정적 사이트를 만듭니다.
  • Playwright, 링크, 번역, 미디어, 피드 계약 검사가 배포 전에 실행됩니다.

다음 단계

  • 검토한 첫 글과 논문 읽기 기록을 공개합니다.
  • 공개 자료가 늘어도 탐색을 단순하게 유지합니다.
